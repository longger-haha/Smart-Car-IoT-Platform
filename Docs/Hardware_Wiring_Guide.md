### 2.2 LM2596 设置步骤

1. 先不接 ESP32，只接电池到 LM2596 输入端
2. 用万用表直流电压档测量 LM2596 输出端
3. 用小螺丝刀调节蓝色电位器旋钮
4. 将输出电压调至 **5.0V** (误差 ±0.1V)
5. 断开电池，确认无误后再接 ESP32

### 2.3 电源规格参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 电池组电压 | 9.0V ~ 12.6V | 3节串联, 3.0V~4.2V/节 |
| LM2596 输出 | 5.0V (恒定) | 给 ESP32 和逻辑部分供电 |
| L298N 驱动电压 | 直接电池电压 | 电机需要大电流,不能降压 |
| ESP32 工作电流 | ~200mA (峰值800mA) | WiFi发射时电流较大 |
| 单个电机堵转电流 | ~2A (TT电机) | 4个电机同时启动约6-8A |

### 5.3 为什么TX/RX要交叉?

```
正常情况下的串口通信规则:

  设备A的TX (发送端)  ──→  设备B的RX (接收端)
  设备A的RX (接收端)  ←─  设备B的TX (发送端)

应用到GPS和ESP32:

  GPS的TX (发送定位数据)  ──→  ESP32的GPIO16/RX2 (接收数据)
  GPS的RX (接收配置命令)  ←─  ESP32的GPIO17/TX2 (发送数据)

⚠️ 如果接反了:
  - GPS的TX接到ESP32的TX → 两边都在发送, 无法通信!
  - 结果: 收不到任何定位数据
```

### 5.4 GPS 使用提示

1. **首次定位时间**: 冷启动需1~5分钟, 之后热启动几秒即可
2. **使用环境**: 户外开阔处最佳, 室内/地下室可能无法定位
3. **天线**: 确保天线朝上, 不要被金属遮挡
4. **波特率**: 默认9600bps, 固件已配置
5. **指示灯**: 模块上LED闪烁频率表示卫星数量 (越快=越多)

### 6.2 MPU6050 接线表 (I²C协议)

| MPU6050引脚 | 连接到ESP32 | 说明 |
|:-----------:|------------|------|
| **VCC** | 3V3 | 电源 (必须3.3V!) |

### 6.3 I²C总线说明

```
I²C (Inter-Integrated Circuit) 是一种两线制串行总线:

  ESP32 GPIO22 (SCL) ────┬─── MPU6050 SCL
                         │
                         R 4.7KΩ (上拉电阻, 大多数模块自带)
                         │
  ESP32 GPIO21 (SDA) ────┼─── MPU6050 SDA
                         │
                        GND

💡 大多数MPU6050模块已经集成了上拉电阻 (4.7KΩ),
   所以通常不需要额外添加。
   
💡 如果I²C通信失败, 检查:
   1. AD0是否接地 (确保地址是0x68)
   2. 上拉电阻是否存在
   3. 接线是否牢固
```

### 6.4 MPU6050 功能说明

| 功能 | 测量范围 | 用途 |
|------|---------|------|
| 加速度计 X/Y/Z | ±2g / ±4g / ±8g / ±16g | 检测倾斜角度、运动状态 |
| 陀螺仪 X/Y/Z | ±250°/s / ±500°/s / ±2000°/s | 检测旋转角速度、航向变化 |
| 温度传感器 | -40°C ~ +85°C | 内部温度补偿 |

固件中使用 **互补滤波算法** 融合加速度计和陀螺仪数据, 得到精确的航向角:

```
最终航向 = 0.98 × (上次航向 + 陀螺仪积分) + 0.02 × 加速度计计算出的航向
```

| **GND** | GND | 公共地 |

### 7.3 工作原理

```
HC-SR04 测距原理 (超声波时间差法):

  时间轴:
  ─────────────────────────────────────────────────────►
  
  ESP32发出触发脉冲:
  Trig:  ______________█__________  (高电平 ≥10μs)
         ↑            ↑
       t=0          t=10μs
  
  HC-SR04工作过程:
  
  ① 发送8个40kHz超声波脉冲
  
  ② Echo变为高电平 (开始计时):
  Echo: _______/‾‾‾‾‾‾‾‾‾‾‾‾\______
              ↑                   ↑
           开始收到回波          回波结束
  
  ③ 计算距离:
     距离(cm) = 高电平时间(μs) × 0.034 / 2
              = 高电平时间(μs) × 0.017
     
  示例: Echo高电平持续了 1176μs
       距离 = 1176 × 0.017 = 20 cm
```

### 7.4 性能参数

| 参数 | 值 |
|------|-----|
| 工作电压 | DC 5V |
| 静态电流 | < 2mA |
| 电平输出 | 高 5V, 低 0V |
| 感应距离 | 2cm ~ 400cm |
| 测距精度 | 约 3mm |
| 测量角度 | < 15° (锥形区域) |

```

```

### 8.4 DHT11 vs DHT22 对比

| 特性 | DHT11 | DHT22 (AM2302) |
|------|-------|----------------|
| 温度范围 | 0°C ~ 50°C | -40°C ~ 80°C |

| 测量精度 | ±2°C / ±5% RH | ±0.5°C / ±2% RH |
| 采样周期 | ≥ 1秒 | ≥ 2秒 |

> 固件默认使用 DHT11。如用 DHT22, 只需修改代码中的 `#define DHT_TYPE DHT22` 即可。

## 9. 电池电压监测电路

### 9.1 为什么要分压?

```
问题: ESP32的ADC最大只能测量 3.3V
      但电池电压高达 11.1V (3节串联)

解决: 使用电阻分压将电压降到安全范围内

公式: V_out = V_in × R2 / (R1 + R2)

设置: R1 = 100KΩ, R2 = 10KΩ
      
      分压比 = 10K / (100K + 10K) = 1/11 ≈ 0.0909
      
      当电池 = 12.6V (满电):
      V_out = 12.6V × 1/11 ≈ 1.15V ✅ 安全!
      
      当电池 = 9.0V (欠压):
      V_out = 9.0V × 1/11 ≈ 0.82V ✅ 安全!
```

### 9.2 分压电路接线

```
                    电池正极 (+11.1V)
                         │
                         │
                    ┌────┴────┐
                    │  R1     │  100KΩ (1/4W以上功率)
                    │ 100KΩ   │
                    └────┬────┘
                         │
                         ├── GPIO35 (ADC1_CH7) 
                         │   ESP32读取此点电压
                         │
                    ┌────┴────┐
                    │  R2     │  10KΩ
                    │  10KΩ   │
                    └────┬────┘
                         │
                    GND (电池负极)


ESP32内部计算真实电压:
  realVoltage = adcReading × (3.3 / 4095) × (R1 + R2) / R2
              = adcReading × 0.00080586 × 11
              = adcReading × 0.008864
```

### 9.3 电池状态判断标准

| 电压范围 | 状态 | 百分比 | 处理措施 |
|---------|------|:-----:|---------|
| > 12.0V | 🔋 满电 | 90%~100% | 正常运行 |
| 11.0V ~ 12.0V | 🟢 正常 | 45%~90% | 正常运行 |
| 10.5V ~ 11.0V | 🟡 低电量 | 0%~45% | 发出警告 |
| < 10.5V | 🔴 严重不足 | 0% | 强制停车! |

## 11. 接线检查清单

### 🔧 上电前必检项目

- [ ] **电源部分**
  - [ ] LM2596 已调至 5.0V (用万用表确认!)
  - [ ] 电池正负极没有接反
  - [ ] L298N 的 +12V 接的是电池正极 (不是5V!)
  - [ ] 所有模块的 GND 都连在一起 (共地!)

- [ ] **电机驱动**
  - [ ] L298N 的 IN1/IN2/IN3/IN4 分别接到 GPIO25/26/27/14
  - [ ] L298N 的 ENA/ENB 分别接到 GPIO12/13
  - [ ] 电机两根线正确接在 OUT1/OUT2 和 OUT3/OUT4
  - [ ] 电机螺丝拧紧, 无松动

- [ ] **GPS模块**
  - [ ] GPS 的 TX 接到 ESP32 的 GPIO16 (不是GPIO17!)
  - [ ] GPS 的 RX 接到 ESP32 的 GPIO17 (不是GPIO16!)
  - [ ] 天线朝上放置, 无金属遮挡
  - [ ] VCC 接到了 3V3 或 5V

- [ ] **MPU6050**
  - [ ] SDA 接 GPIO21, SCL 接 GPIO22 (不要接反!)
  - [ ] AD0 接到了 GND (地址设为0x68)
  - [ ] VCC 接 3V3 (不要接5V!)
  - [ ] 模块上的上拉电阻存在 (或自行外接4.7KΩ)

- [ ] **HC-SR04**
  - [ ] Trig 接 GPIO5, Echo 接 GPIO18
  - [ ] VCC 接 5V (不要接3.3V, 可能不稳定!)
  - [ ] 发射头和接收头没有被物体遮挡

- [ ] **DHT11**
  - [ ] 面对网孔, 从左数第2脚(DATA)接GPIO4
  - [ ] 最左脚(VCC)接3V3, 最右脚(GND)接GND
  - [ ] 有上拉电阻 (10KΩ从DATA拉到VCC)

- [ ] **其他**
  - [ ] 电池分压电阻正确: 100KΩ串联, 10KΩ并联到GND
  - [ ] 分压中间点接到 GPIO35
  - [ ] 所有杜邦线插紧, 无虚接
  - [ ] 没有裸露导线短路风险

### ⚡ 上电测试顺序

```
步骤1: 断开所有电源开关
       ↓
步骤2: 目视检查所有接线 (对照上面的清单)
       ↓
步骤3: 接通电池 → LM2596 有输出指示灯亮
       ↓
步骤4: 用万用表再确认一次LM2596输出为5.0V
       ↓
步骤5: 接通ESP32电源 → 板载LED闪烁后常亮/熄灭
       ↓
步骤6: 打开串口监视器 (115200 baud)
       ↓
步骤7: 观察启动日志:
       - "[MOTOR] 初始化完成" → 电机OK
       - "[IMU] ✅ MPU6050检测成功" → 陀螺仪OK
       - "WiFi connected" → 网络OK
       - "[MQTT] Connected" → MQTT服务器OK
       ↓
步骤8: 如一切正常, 安装车轮进行路试!
```

## 12. 常见问题排查

### ❓ 问题1: ESP32不上电 / 不启动

| 可能原因 | 解决方法 |
|---------|---------|
| LM2596没调好 | 万用表测输出, 调到5.0V |
| 电源线太细/太长 | 换粗短线, 减少压降 |
| USB线和电池同时供电 | 只用一种供电方式 |
| GPIO2被外部拉低 | 断开GPIO2的外部连接 |

### ❓ 问题2: 电机不转 / 转向反了

| 可能原因 | 解决方法 |
|---------|---------|
| L298N +12V没接电池 | 必须直接接电池正极! |
| ENA/ENB没接PWM | 接到GPIO12/13 |
| 电机线接反 | 交换OUT1/OUT2或OUT3/OUT4的两根线 |
| 电池电量不足 | 充电或换新电池 |

### ❓ 问题3: GPS搜不到星 / 无数据

| 可能原因 | 解决方法 |
|---------|---------|
| TX/RX接反了 | GPS-TX→GPIO16, GPS-RX→GPIO17 |
| 在室内测试 | 移到户外开阔处 |
| 首次使用 | 冷启动需等1~5分钟 |
| 波特率不对 | 默认9600, 固件已设置 |
| 天线接触不良 | 重新插紧天线 |

### ❓ 问题4: MPU6050检测不到

| 可能原因 | 解决方法 |
|---------|---------|
| SDA/SCL接反 | SDA→GPIO21, SCL→GPIO22 |
| AD0悬空 | 接AD0到GND |
| I²C地址错误 | 检查是否为0x68 |
| 缺少上拉电阻 | 加4.7KΩ上拉到VCC |
| 接触不良 | 重新插拔杜邦线 |

### ❓ 问题5: 超声波读数为0或999

| 可能原因 | 解决方法 |
|---------|---------|
| Trig/Echo接反 | Trig→GPIO5, Echo→GPIO18 |
| 供电不足 | 必须接5V, 不能用3.3V |
| 距离超出范围 | 有效范围2cm~400cm |
| 发射/接收头脏污 | 用棉签清洁 |
| 干扰源附近 | 远离超声波干扰源 |

### ❓ 问题6: DHT11读数异常

| 可能原因 | 解决方法 |
|---------|---------|
| DATA接错引脚 | 应该接GPIO4 |
| 缺少上拉电阻 | 加10KΩ上拉 |
| 采样间隔太短 | 至少间隔1秒以上 |
| 线太长 | DHT11建议线长<20cm |
| 模块损坏 | 更换新的DHT11 |

### ❓ 问题7: WiFi连不上

| 可能原因 | 解决方法 |
|---------|---------|
| SSID/密码错误 | 修改固件中的 WIFI_SSID 和 WIFI_PASSWORD |
| 距离路由器太远 | 靠近路由器或增加中继 |
| 2.4GHz/5GHz混淆 | ESP32只支持2.4GHz |
| 路由器MAC过滤 | 在路由器白名单添加ESP32 |

### ❓ 问题8: MQTT连接失败

| 可能原因 | 解决方法 |
|---------|---------|
| MQTT_HOST填错 | 填写电脑/服务器的局域网IP |
| Mosquitto未运行 | `docker-compose up mosquitto` |
| 防火墙拦截 | 开放1883端口 |
| IP地址变了 | 重新获取服务器IP |
